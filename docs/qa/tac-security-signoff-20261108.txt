OPEN LIMITATION 1 — LEAKED PASSWORD PROTECTION

Development leaked-password protection remains disabled. The valtoris organization was confirmed on Supabase Free on November 8, 2026; Supabase requires Pro or above for this feature.

Consequence: the hosted development Auth configuration does not screen passwords against the leaked-password service. A reused or compromised password could therefore be accepted. Strong random passwords for the three test accounts reduce their reuse risk but do not establish equivalent protection for every account.

Decision needed: either separately authorize an eligible plan upgrade and then enable and verify protection, or explicitly accept the limitation for the named development candidate. No plan upgrade, charge, or security-setting change is authorized by preparing this document. A development exception does not carry over to production.

Reference:
https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection

REVIEWED RESIDUAL RISK 2 — PRIVILEGED DATABASE FUNCTIONS

Supabase still reports 90 authenticated SECURITY DEFINER execution warnings. These functions run with elevated database privileges and depend on correct authorization inside each callable path.

Reviewed controls:
- Anonymous EXECUTE is denied for all 90 flagged functions.
- All 90 have a fixed per-function search_path.
- Neither anonymous nor authenticated roles can CREATE objects in public/extensions, and neither is superuser or BYPASSRLS.
- The reviewed function bodies contain no dynamic EXECUTE or user_metadata authorization references.
- Shared household/application guards, private intake delegation, requirement access checks, and the commission writer's internal owner guard were traced.
- Rollback-only QA-advisor probes returned not_authorized for 27 functions with an immediate owner assertion and for the standard commission wrapper: 28 entry points total.

Remaining risk: authenticated EXECUTE grants remain, and a missed authorization defect in a conditional path could expose or change another user's records. The null-argument probes establish the initial owner gate; they do not prove every valid payload or every path across all 90 functions. Full-suite permission tests provide additional evidence. No new bypass was confirmed within this review.

Acceptance condition: retain explicit function-level authorization and permission regression tests, and review changes to grants, guards, or callable paths before extending this signoff.

Reference:
https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable
